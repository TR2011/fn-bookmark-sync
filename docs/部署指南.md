## 环境要求

| 项目 | 要求 |
| --- | --- |
| 飞牛 fnOS | 建议 ≥ 1.1.8；若系统不识别 `platform=all`，换用 `dist/edge-bookmarks_1.4.0_x86.fpk` 或 `..._arm.fpk` |
| 架构 | x86_64 / ARM 均可（纯 Python，无原生二进制） |
| **Python 3** | **必须**：fnOS 默认不预装。先在应用中心安装官方 `python312` 运行时 |
| 端口 | **8765/tcp**（浏览器插件 / 局域网访问）。桌面统一网关入口不占用对外端口。v1.4.0 仍通过 `config/resource` 的 `port-config` + `EdgeBookmarks.sc` 声明放行 |
| 浏览器 | Chromium 系（Edge / Chrome / Brave / Vivaldi / Opera 等）≥ 91，Manifest V3 |
| 网络 | 管理界面：任意网络（走飞牛当前域名）；插件同步：局域网可达 8765、外网备用地址，或**统一登录地址 + 反代路径** |
| 统一网关 | fnOS 需支持 `gatewayPrefix` / `gatewaySocket`（唯一桌面入口依赖它）。若网关不通，可用 `http://<NAS-IP>:8765` 直接打开管理页 |

> 应用以 `run-as: package` 的专用用户 `edgebm` 运行，不需要 root，只在自己的数据卷内读写。网关通道由飞牛校验 NAS 登录态后转发到 `${TRIM_APPDEST}/app.sock`；**应用自身的账号密码还要再登录一次**。

## 一、安装 FPK

0. **先装运行时**：应用中心搜索 `python312` → 安装。跳过会导致「装得上但服务起不来」。
1. 应用中心 →「手动安装」→ 上传 `dist/edge-bookmarks_1.4.0_all.fpk`。
   - 若因 `port-config` 声明安装失败，改用 `edge-bookmarks_1.4.0_all_noport.fpk` 对照包（`resource={}`、不含 `.sc`）。
2. 同意协议，选择安装空间，等待完成，确保应用卡片显示「运行中」。
3. 桌面**只出现一个图标**：**Fn收藏夹同步**。点击会自动弹出一个新页面（走统一网关）。入口未刷新时按 [点开无反应排查](点开无反应排查.md) 重启应用中心。

v1.4.0 安装 / 启动流程：

```
install_init      纯 exit 0（不检查环境、不建目录、不写文件）
install_callback  纯 exit 0
main start        ① 检测 Python 3
                  ② 创建 $TRIM_PKGVAR / $TRIM_PKGETC
                  ③ 清理旧版遗留的 token.txt
                  ④ 清理陈旧 app.sock，导出 EB_GATEWAY_SOCKET / EB_GATEWAY_PREFIX
                  ⑤ 启动 server.py：同时监听 TCP 8765 与 Unix Socket
                     （首次启动自动建 config.json 与 bookmarks.db；旧库自动迁移并合并重复书签）
                  ⑥ 30 秒内轮询 /api/v1/health 探活，记录网关 Socket 状态
```

> 安装期钩子刻意零副作用：fnOS 以降权用户执行它们，任何非 0 退出都会被包装成「无法创建应用程序目录」。

命令行安装（可选）：

```bash
sudo trim-cli app install-fpk /path/to/edge-bookmarks_1.4.0_all.fpk --volume-id 1 --yes
sudo appcenter-cli start edge-bookmarks
sudo appcenter-cli status edge-bookmarks
```

## 二、首次打开：注册管理员

点击桌面图标 → 第一次会显示「**首次使用 · 注册管理员**」：

| 字段 | 要求 |
| --- | --- |
| 管理员用户名 | 2–32 位，支持中文、字母、数字、`_ . - @`，唯一 |
| 显示名称 | 可选，界面展示用 |
| 密码 | 6–128 位（PBKDF2-HMAC-SHA256 加盐迭代存储，不保存明文） |
| 确认密码 | 与上一致 |

创建后自动登录进入管理界面。**注册入口只在没有任何用户时出现，且只能成功一次**。会话有效期 30 天，过期后插件会用保存的账号密码自动重登。

> 忘记管理员密码：目前没有其他管理员可以帮你重置，只能删除 `$TRIM_PKGVAR/bookmarks.db` 重新初始化（**会清空全部书签**，请先备份 `exports/` 里的 HTML）。

## 三、给其他成员开账号（可选）

管理界面 →「**用户管理**」（仅管理员可见）：

- 「添加用户」：填用户名、显示名、初始密码、角色（普通用户 / 管理员）。
- 「重置密码」：立即让该用户所有网页与插件会话失效。
- 「删除」：同时清空该用户的设备、书签、快照、日志，不可恢复。不能删除当前登录账号，也不能删除最后一个管理员。

每个用户**只同步、查看、管理自己的收藏夹**。把账号密码告诉对方，对方在插件里粘贴自己账号的配置即可。普通用户看不到「用户管理」标签，调用相关接口返回 403。

## 四、连接浏览器插件（地址自动识别）

管理界面「**连接浏览器插件**」默认折叠成一行（`summary` 里直接有「复制插件配置」按钮），点开后**全部只读**，没有任何输入框：

- **插件主地址（推荐）** —— 服务端按当前访问方式自动推算，附「复制」按钮。
- **插件登录账号** —— 当前登录用户名。
- **插件备用地址** —— 自动给出，无可用候选时隐藏。
- **候选地址列表**（折叠）—— 逐条列出推荐 / 备用 / 统一登录地址 + 反代路径 / 局域网直连，方便核对。
- **配置预览**（折叠）—— 展开可看到将要复制的 JSON。
- **「复制插件配置」** —— 一键复制下面这样的配置：

```json
{
  "serverUrl": "https://nas.example.com:9443/app/edge-bookmarks",
  "serverUrlAlt": "http://192.0.2.10:8765",
  "serverUrls": ["http://nas.example.com:8765"],
  "username": "admin"
}
```

> 出于安全，复制的配置**不含密码**；密码在插件设置页输入一次。**不再有访问令牌、不再有 `token.txt`**。
>
> **`serverUrl` 就是当前管理页地址**（上例即你地址栏里的 `/app/edge-bookmarks`）。旧版会显示一个未配置的 `/eb-api`，实测为 404，现已修正；未配置反代时该路径不会出现在配置里。
>
> 插件请求会携带浏览器凭证，复用当前浏览器里已登录的飞牛会话走统一网关；若网关返回 `invalid token`（要求 NAS 登录），health 探测判为失败并自动切换到局域网直连 `http://<NAS-IP>:8765`。外网长期稳定使用仍需把 8765 映射出去或配置独立反代，详见 [反向代理与统一登录地址](反向代理与统一登录地址.md)。

### 安装插件

1. 解压 `dist/edge-bookmarks-extension_1.4.0.zip` 到**固定目录**。
2. 浏览器扩展页开启「开发人员模式」→「加载解压缩的扩展」选中解压目录：Edge / Chrome / Brave / 多数国产浏览器用 `chrome://extensions`（Edge 亦支持 `edge://extensions`），Vivaldi 用 `vivaldi://extensions`，Opera 用 `opera://extensions`。完整说明见 [多浏览器支持](多浏览器支持.md)。
3. 插件设置页 **① 粘贴插件配置**（粘贴后自动解析）→ **② 输入本应用密码** →「保存并立即同步」。
4. 如需核对，可点「测试连接并登录」；成功时显示实际命中的地址、账号与服务端版本。

插件按「上次可用 → 主地址 → 备用地址 → 其余候选」逐个探测 `/api/v1/health`，任一可达即可，**不需要用户判断该填哪个地址**，也无需再填反代路径。会话过期、服务重启或管理员重置密码后，会用保存的账号密码自动重登一次（密码变了需手动更新）。

同步成功后：插件弹窗显示「已同步」与当前登录账号；Web 界面「设备」页出现这台设备；`$TRIM_PKGVAR/exports/` 下出现该用户的 `bookmarks-latest.html` 与 `bookmarks-<用户名>-latest.html`。

### 同步策略建议

| 场景 | 推荐配置 |
| --- | --- |
| 只做 NAS 备份 | 定时 15 分钟 + 变动自动同步；「拉取」关闭 |
| 同一用户多台电脑互见书签 | 开启「拉取」，导入「其他收藏夹 → 来自飞牛 NAS」，按 URL 去重 |
| 收藏夹极多（> 1 万条） | 间隔调到 1 小时以上，关闭「变动自动同步」 |

> 拉取只会**新增**书签，绝不删除或改写浏览器里已有内容；被导入的目录在上传时会自动剔除，不会自我循环。

### 按设备标签拉取与同步策略自动保存

- 插件弹窗「更多操作 → 拉取其他设备书签」下会列出**本账号的其他设备标签**（名称 + 书签数），点选后按「拉取所选设备」只导入这台设备提供过的书签；选「全部」则导入全部云端书签。标签来自 `/api/v1/devices`，本机自动排除。
- 设置页「同步策略」卡片的四个控件（定时自动同步、变动时同步、顺带拉取、同步间隔）**改动即自动保存**，卡片底部显示「✓ 已自动保存，定时计划已更新」；也可点「保存策略」显式保存。策略单独走 `SAVE_STRATEGY`，不会要求重新输入密码，也不会覆盖连接信息。

### 把本机历史备份拉回浏览器

插件弹窗点「更多」展开，里面有**历史备份**下拉框（只列**本设备**的快照，按时间倒序）和「拉回浏览器」按钮：

| 行为 | 说明 |
| --- | --- |
| 目标目录 | 在「其他收藏夹」下的同步目录里新建 `本机历史备份 MM-DD HH:mm`，**不会覆盖现有书签** |
| 去重 | 逐个比对浏览器里已有网址，已存在的一律跳过，结果提示「已还原 N 条，跳过 M 条已存在」 |
| 空结果 | 全部被跳过时会自动删掉刚建的空目录，不留垃圾 |
| 不触发连锁同步 | 还原期间抑制书签变更监听，不会因为一次还原又触发一轮上传 |

> 单次最多还原 1500 条，超大备份请分几次选不同时间点。还原只做「补回」，不会删除你后来新增的书签。

## 五、管理端页面

顶栏一条合并统计：设备数 / 书签数 / 快照数 / 最近同步时间；**点快照数可直接跳到快照管理**。「连接浏览器插件」默认折叠，点开才有候选地址与 JSON 预览。

### 1）设备

| 操作 | 说明 |
| --- | --- |
| 看设备 | 列表展示每台设备的名称、浏览器、书签数、最近同步；整行点击进入该设备管理页 |
| 看目录 | 设备管理页**保留该设备同步时的原目录树**，文件夹可折叠 |
| 选 | 每条书签可勾选；文件夹勾选联动全部子项，部分选中显示半选态；工具栏有「全选」 |
| 改目录 | 选中后点「修改文件夹」→ 填目标路径（留空=根目录）→ 批量移动；移动后转「手动维护」，不会被下次同步按旧目录覆盖回去 |
| 删 | 勾选后批量删除，进入回收站，后续同步跳过这些网址 |
| 回收站 | 该设备视角的回收站列表，可单条恢复，也可**一键清空**（清空后下次同步会重新带回） |

### 2）书签浏览（只读）

- 顶部是「全部 + 每台设备」的标签，点标签按设备筛选。
- 下方是**去重后的目录树**，每条书签后标注来自哪几台设备（多个角标）。
- 本页**不含任何选中、编辑、删除按钮**，纯浏览；需要改动请回「设备」或「书签管理」。

### 3）书签管理（增删改查）

| 操作 | 说明 |
| --- | --- |
| 查 | 全量列表 + 标题/网址筛选 + 分页；顶部显示「原始来源数 → 保留数 → 去除重复数」 |
| 增 | 标题 + 网址 + 可选路径；重复网址返回 409 |
| 改 | 改标题 / 网址 / 路径；改过网址的条目转为「手动维护」，同步不会覆盖 |
| 删 | 单条或勾选批量删除；删除后同步自动跳过该网址 |
| 恢复 | 回收站可恢复；「彻底移除」则允许浏览器下次同步重新带回 |

去重规则：忽略 `http`/`https` 差异、大小写、默认端口、末尾斜杠、`#锚点`、`utm_*` 等跟踪参数、查询参数顺序；保留路径与有意义的查询参数。导出 HTML / CSV / JSON、搜索与回灌都是去重后的数据。完整接口见 [API](API.md)。

### 4）快照

| 操作 | 说明 |
| --- | --- |
| 筛选 | 顶部设备标签「全部 + 每台设备」，点标签只看该设备的快照 |
| 列表 | 时间、设备名、书签数、体积；分页显示，共 N 份 |
| 查看 | 弹窗里按**原始目录结构**只读展示这棵书签树（可折叠文件夹） |
| 下载 | 在列表行或预览弹窗选 **HTML / CSV / JSON** 后下载，文件名为 `snapshot-<id>-<时间>.<格式>`；HTML 保留原始目录树、CSV 是扁平表格 |
| 删除 | 单份删除、勾选批量删除、清空某设备、清空全部；都有二次确认 |
| 不影响数据 | 删除只清理历史快照，当前书签与回收站都不动；设备下次同步会生成新快照 |

> 每台设备自动保留最近 10 份快照（超出自动清理）。设置页「历史快照」也有「打开快照管理」入口。

## 六、数据位置

| 内容 | 路径（FPK 环境变量） |
| --- | --- |
| 可执行程序 | `$TRIM_APPDEST/bin/server.py`、`$TRIM_APPDEST/web/` |
| 统一网关 Socket | `$TRIM_APPDEST/app.sock`（停止时清理） |
| 启动留痕 | `$TRIM_PKGVAR/STARTUP_STATUS.txt` |
| 运行参数 | `$TRIM_PKGETC/config.json`（**不含任何令牌**） |
| **SQLite 数据库** | `$TRIM_PKGVAR/bookmarks.db`：`users` / `sessions` / `devices` / `bookmarks` / `bookmark_sources` / `tombstones` / `snapshots` / `logs`（含 WAL） |
| 运行日志 | `$TRIM_PKGVAR/server.log` |
| PID 文件 | `$TRIM_PKGVAR/server.pid` |
| 自动导出 | `$TRIM_PKGVAR/exports/bookmarks-latest.html`、`bookmarks-YYYYMMDD.html`、`bookmarks-<用户名>-latest.html` |

典型绝对路径：`/vol1/@appdata/edge-bookmarks/bookmarks.db`。

**升级与卸载都不会删除数据库**。旧库升级会自动补列、重建书签表、回填去重键并**合并历史重复项**（不丢书签）；`token.txt` 会在启动时清理。

## 七、排障命令

```bash
# 应用状态（0=运行中，3=未运行）
sudo /var/apps/edge-bookmarks/cmd/main status; echo $?

# 服务端健康探测：应返回 needsAdminSetup / authMode
curl http://127.0.0.1:8765/api/v1/health

# 关键二分：从「电脑」再测一次
# curl http://<NAS-IP>:8765/api/v1/health
#   本机通 / 电脑不通 → 防火墙未放行 8765（检查 port-config 与 EdgeBookmarks.sc）
#   本机也不通       → 服务没起来，看 STARTUP_STATUS.txt

# 用账号密码登录（应返回 token 与 user）
curl -X POST -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Example@123456"}' \
  http://127.0.0.1:8765/api/v1/auth/login

# 查看服务端自动推算的插件地址（需登录）
curl -H 'Authorization: Bearer <token>' \
  http://127.0.0.1:8765/api/v1/plugin-config

# HTTP Basic 直接读状态（含去重统计）
curl -u admin:Example@123456 http://127.0.0.1:8765/api/v1/status

# 反代路径是否生效
# curl -i https://nas.example.com:9443/eb-api/api/v1/health
#   期望 200 且 JSON 里 "base":"/eb-api/"

# 统一网关 Socket 是否存在、权限是否允许网关进程访问
ls -l /var/apps/edge-bookmarks/target/app.sock

# 启动留痕 / 服务日志
sudo cat /var/apps/edge-bookmarks/var/STARTUP_STATUS.txt
sudo tail -n 100 /var/apps/edge-bookmarks/var/server.log

# 手动重启 / 端口占用
sudo /var/apps/edge-bookmarks/cmd/main stop && sudo /var/apps/edge-bookmarks/cmd/main start
sudo ss -ltnp | grep 8765

# 查看账号、书签数与去重来源（需 NAS 上有 sqlite3）
sudo sqlite3 /vol1/@appdata/edge-bookmarks/bookmarks.db \
  'select id,username,role from users;
   select count(*) from bookmarks;
   select count(*) from bookmark_sources;
   select count(*) from tombstones;'
```

| 症状 | 排查 |
| --- | --- |
| 应用一直「启动中」 | 看 `server.log`；**最常见是没装 `python312`**，装好后点「启动」即可；再确认 8765 未被占用 |
| 单图标打不开 / 白屏 | 先查 `STARTUP_STATUS.txt` 是否记录「统一网关 Socket 已建立」；确认 `gatewayPrefix` 与 `EB_GATEWAY_PREFIX` 一致；入口缓存则重启 `trim_app_center.service`。可临时用 `http://<NAS-IP>:8765` 直接打开确认服务正常 |
| 首次打开没有注册表单 | 数据库里已有用户；用已有账号登录 |
| 插件提示「用户名或密码错误」 | 与 Web 界面同一套账号；管理员重置密码后插件也要改密码 |
| 插件提示 410 | 仍在用旧插件，升级到 `edge-bookmarks-extension_1.4.0.zip` |
| 插件「以下地址均探测失败」 | 管理端复制的配置含多个候选地址，插件会逐个探测；错误信息逐条列出实际 URL 与原因。先 NAS 本机、再电脑分别测 health；确认反代 location 未落在飞牛登录校验之后 |
| 反代路径 404 / 返回登录页 | 核对 location 路径、`proxy_pass` 尾斜杠与 `X-Forwarded-Prefix`；返回登录页说明规则落在应用网关鉴权后面 |
| 离开内网后插件不同步 | 统一网关地址需要浏览器已登录飞牛；若网关返回 `invalid token`，需把 8765 映射出去（DDNS + 端口映射，FN Connect 通常不转发自定义端口）或配置独立 HTTPS 反代 |
| 书签数显示 0 | 确认插件有 `bookmarks` 权限；手动点一次「立即同步」 |
| 删除的书签又回来了 | 正常删除会进回收站并被同步跳过；若点了「彻底移除」，则允许浏览器重新带回 |
| 某用户看不到之前同步的书签 | 检查插件里登录的是不是同一个账号；旧版历史数据归属首个注册的管理员 |

## 八、内外网访问

**管理界面**：统一网关把唯一入口挂在当前飞牛域名下（`/app/edge-bookmarks`），内网、HTTPS 域名、FN Connect 都自动可用，由飞牛负责 NAS 登录校验；不需要为它开放或映射 8765。**打开页面后仍需输入应用账号密码**。

**插件同步**：复制配置里的主地址就是当前管理页地址，另有局域网直连等候选，插件逐个探测、任一可用即连，界面无需填写。

| 场景 | 做法 |
| --- | --- |
| 只在家里用 | 直接复制管理端配置；网关不通时插件自动命中局域网直连 `http://<NAS-IP>:8765` |
| 浏览器已登录飞牛 NAS | 插件携带浏览器凭证走统一网关 `/app/…`，可与桌面共用同一个域名，无需 8765 端口映射 |
| **外网长期稳定使用** | 若网关返回 `invalid token`：把 8765 映射出去，或在登录地址上加一条**独立、不受飞牛应用网关登录校验**的反代 location（如 `/eb-api`）；然后用该反代地址打开管理页，主地址会自动变成它 |
| 笔记本经常带出去 | 同上；或确认复制配置里含 DDNS + 8765 映射地址 |
| 用 HTTPS 反代 | 使用受信任证书；反代需透传 `Authorization` 头与 `OPTIONS` 预检 |

> 未配置反代时，服务端**不会**再自动生成一个 `/eb-api` 地址。实测该路径在多数 NAS 上返回 404。

> 安全提醒：直连通道的账号密码 / 会话令牌在 HTTP 上明文传输，公网暴露 8765 前建议套 HTTPS 反代或限制来源 IP。

## 九、修改端口

端口在 3 处保持一致，改完重新打包：

| 文件 | 字段 |
| --- | --- |
| `fpk/manifest` | `service_port` |
| `fpk/EdgeBookmarks.sc` | `src.ports` / `dst.ports`，例如 `8765/tcp` |
| `README.md` / 插件设置页 | 文档中的默认地址与用户填写的地址 |

`cmd/main` 自动读取 `TRIM_SERVICE_PORT`，无需修改；v1.4.0 的 `ui/config` 只有一个网关入口，**不声明 port**。`.sc` 必须与 `service_port` 同步改，否则防火墙放行的还是旧端口。
