# 多浏览器支持

> **v1.4.0 更新**：界面现代化 + 代码精简 + 开源发布，开发者统一为 oldkevin。插件品牌中立策略不变：不写死「Edge」，统一为「Chromium 系浏览器」；`minimum_chrome_version` 为 **91**；设备名按真实 UA 识别品牌。本文说明支持范围、各浏览器加载方式与已知限制。

---

## 一、结论

浏览器插件是**纯标准 Manifest V3**，只调用 5 个 `chrome.*` 标准命名空间：

| API | 用途 |
| --- | --- |
| `chrome.bookmarks` | 读取 / 创建 / 删除收藏夹与目录 |
| `chrome.storage.local` | 保存配置与会话令牌 |
| `chrome.alarms` | 定时同步与变更防抖 |
| `chrome.runtime` | 消息、启动事件、打开设置页 |
| `chrome.tabs` | 打开管理界面 |

**没有任何 Edge 专有 API**，也没用 Firefox 的 `browser.*`。这 5 个 API 由 Chromium 项目本身提供，所有 Chromium 内核浏览器都实现。因此：

- ✅ **Edge / Chrome / Brave / Vivaldi / Opera 及多数国产 Chromium 浏览器**：功能完全一致，可直接同步。
- ❌ **Firefox / Safari**：非 Chromium 内核，MV3 service worker 与 `chrome.bookmarks` 均不兼容，无法使用。
- 服务端 `/api/v1/*` 只认「账号密码 + `clientId`」，**与浏览器品牌无关**，无需任何改动。

## 二、支持矩阵

| 浏览器 | 内核要求 | 扩展页入口 | 加载方式 | 备注 |
| --- | --- | --- | --- | --- |
| Microsoft Edge | ≥ 91 | `edge://extensions`（也支持 `chrome://extensions`） | 开发人员模式 → 加载解压缩的扩展 | 设计目标，推荐 |
| Google Chrome | ≥ 91 | `chrome://extensions` | 开发者模式 → 加载已解压的扩展程序 | 完整可用 |
| Brave | ≥ 91 | `brave://extensions` 或 `chrome://extensions` | 开发者模式 → 加载已解压的扩展程序 | UA 不暴露品牌，设备名会显示为 Chrome（见第五节） |
| Vivaldi | ≥ 91 | `vivaldi://extensions` | 开发者模式 → 加载已解压的扩展程序 | 完整可用 |
| Opera | ≥ 91 | `opera://extensions` | 开发者模式 → 加载已解压的扩展程序 | 完整可用 |
| 国产 Chromium（360 / QQ / 搜狗 / 夸克 / UC / 2345 等） | 多数 ≥ 91 | 多数为 `chrome://extensions`，部分在「设置 → 扩展管理」 | 视版本 | 见第四节注意点 |

## 三、版本门槛为什么是 91

| 项 | 说明 |
| --- | --- |
| 当前版本 | `minimum_chrome_version: "91"` |
| 下限依据 | `background.service_worker` 使用 `"type": "module"`（ES module 形式的 service worker），需要 Chromium **91+**；MV3 本身 88+ 即可 |
| 低于 91 | 只能退回 Manifest V2，本项目不支持，也无法通过下调版本号绕过 |
| 查内核版本 | 地址栏打开 `chrome://version`（Edge 为 `edge://version`），看「Chromium 版本 / Google Chrome」行；国产浏览器若隐藏该页，可用 `chrome://settings/help` 看版本号再对照 |

> 国产浏览器内核版本参差很大（常见 Chromium 86~112）。**若低于 91 就无法安装**，这不是配置问题，只能等浏览器升级内核或换用新版浏览器。

## 四、加载步骤（各浏览器通用）

1. 解压 `fn-bookmark-sync-extension_1.4.0.zip`，记住解压后的目录路径。
2. 打开上表对应的**扩展页**。
3. 开启「开发人员模式 / 开发者模式」开关（Edge、Vivaldi 在左下角，Chrome、Brave、Opera 在右上角）。
4. 点「加载解压缩的扩展 / 加载已解压的扩展程序」，选中第 1 步的目录。
5. 在飞牛管理页「**连接浏览器插件**」点「复制插件配置」，粘贴到插件设置页的「① 粘贴插件配置」，再填「② 密码」。
6. 点「保存并同步」，弹窗状态变为已连接即完成。

### 国产 Chromium 浏览器的注意点

| 现象 | 处理 |
| --- | --- |
| 扩展页打不开或入口被隐藏 | 试 `chrome://extensions`；部分版本要从「设置 → 扩展程序 / 扩展管理」进入，或需先在 `chrome://flags` 打开扩展相关开关 |
| 每次启动弹「请停用开发者模式扩展」 | 属浏览器策略提示，功能通常仍可用；若反复被自动禁用，需改用该浏览器自家扩展商店（本项目未提供商店包） |
| 要求从自家商店安装 | 本项目只分发解压目录，不接受商店审核的浏览器无法使用 |
| 内核版本显示很旧 | 见第三节，低于 91 无解 |
| HTTPS 自签证书 | 先在该浏览器里访问一次 NAS 地址并信任证书，否则插件 `fetch` 会失败 |

> 统一网关通道（`/app/…`）依赖的是**飞牛 NAS 的会话 Cookie**，只要在该浏览器里登录过飞牛桌面即可，与浏览器品牌无关；自签证书信任同理，按浏览器分别处理一次。

## 五、设备名按真实浏览器识别

插件上报的 `browser` 字段与默认设备名由 UA 识别，不再恒定写「Microsoft Edge」。

| UA 标识 | 识别结果 |
| --- | --- |
| `Edg/131…` | Microsoft Edge 131 |
| `OPR/116…` | Opera 116 |
| `Vivaldi/7.1…` | Vivaldi 7 |
| `Brave/…`（旧版） | Brave |
| `Chrome/131…` | Google Chrome 131 |
| `Chromium/…` | Chromium |
| `Quark/` / `UBrowser/` / `QQBrowser/` / `QIHU` / `MetaSr` | 夸克 / UC / QQ / 360 / 搜狗浏览器 |
| 均不匹配 | Chromium 浏览器（中性兜底） |

匹配顺序上**自有标识优先于 `Chrome/`**，因为 Chromium 分支的 UA 普遍同时带两者（例如 Edge 的 UA 里既有 `Chrome/131` 也有 `Edg/131`）。

| 限制 | 说明 |
| --- | --- |
| Brave 新版不暴露品牌 | 出于隐私考虑，Brave UA 与 Chrome 完全一致，会被识别成 Chrome；可在插件设置页「设备名称」手动改成「Brave · Windows」 |
| 历史数据不变 | 已经同步过的设备，其 `browser` 值保持当时上报的原样（例如 `Microsoft Edge 131`），不会回写覆盖 |
| 每台浏览器各占一行 | `clientId` 按浏览器配置文件独立生成，同一台电脑上装 Edge + Chrome 会在「我的设备」里出现两条，这是设计如此，便于分别管理 |

## 六、内部标识不要改

品牌中立化只改**面向用户的文案**，以下历史内部标识全部保持不变：

| 标识 | 位置 | 为什么不能改 |
| --- | --- | --- |
| `appname = edge-bookmarks` | `fpk/manifest`、桌面入口 | 飞牛按 appname 认应用，改名会被当成新应用、旧数据留在原目录 |
| 路径前缀 `/app/edge-bookmarks` | 统一网关地址 | 同上，且反代规则与文档都依赖它 |
| `edgebm` 专用用户 / 组 | 安装钩子 | 数据卷属主，改名会导致权限失效 |
| `EdgeBookmarks.sc` | `config/resource` 端口放行 | 飞牛端口配置引用它 |

产物文件名（`.fpk` 与插件 zip）统一为 `fn-bookmark-sync_*`，仅作分发用途，由构建脚本的 `PACKAGE_NAME` 控制，与上面的内部标识无关。

## 七、常见问题

| 问题 | 回答 |
| --- | --- |
| 装到 Chrome 上，设备列表里显示「Microsoft Edge」 | 说明该设备是旧版同步过的历史记录，或浏览器 UA 被伪装；升级插件后**新同步**的设备会显示真实品牌，旧记录需删除设备后重新同步才会更新 |
| 多个浏览器能共用同一个 NAS 账号吗 | 可以。多用户隔离是按「应用账号」划分的，同一账号下多台浏览器各自成为一台设备，书签自动去重合并 |
| 换浏览器后书签会丢吗 | 不会。数据都在 NAS 的 SQLite 里；新浏览器首次同步后，用插件「更多操作 → 拉取其他设备书签」或「一键拉回」即可取回 |
| 需要给每个浏览器单独配置吗 | 需要。每个浏览器有独立的 `chrome.storage`，各自粘贴一次配置、输入一次密码 |
| Firefox 能用吗 | 不能。`chrome.bookmarks` 与 MV3 service worker 均不兼容，且 Firefox 的书签根节点模型不同 |
