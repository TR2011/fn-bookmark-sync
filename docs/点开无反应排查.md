## 30 秒判断（不用 SSH，先做这一步）

有**两条独立通道**，请分别测：

| 访问地址 | 测的是什么 |
| --- | --- |
| `https://<当前飞牛域名>/app/edge-bookmarks` | 统一网关 → Unix Socket → 服务（桌面入口） |
| `http://<NAS局域网IP>:8765/api/v1/health` | TCP 直连通道（浏览器插件用） |

| 网关地址 | health | 结论 | 跳到 |
| --- | --- | --- | --- |
| 能打开 | 通 | 服务与网关都正常，多半只是**入口缓存** | [二 · 2.3](#23-入口缓存) |
| 打不开 | 通 | 服务活着，问题在**网关 Socket / 前缀** | [二](#二服务正常但网关入口打不开) |
| 打不开 | 不通 | **服务没启动**，多半缺 `python312` | [一](#一服务没启动最常见) |

同时看飞牛「应用中心」里本应用状态：「运行中」/「未运行」/「启动失败」。

## 一、服务没启动（最常见）

fnOS **默认不预装 Python 3**，`python312` 是应用中心里要单独安装的运行时。安装期钩子刻意零副作用，所以**缺 Python 也能装上**，但服务起不来，两条通道都不通。

1. 飞牛「应用中心」搜索 **`python312`** → 安装官方运行时。
2. 回到本应用，点「**启动**」，等约 10 秒。
3. 重新访问 health。**装 python312 不需要重装本应用。**

仍不行，开 SSH：

```bash
# 最关键：启动卡在哪一步、网关 Socket 有没有建立
sudo cat /var/apps/edge-bookmarks/var/STARTUP_STATUS.txt

sudo tail -n 80 /var/apps/edge-bookmarks/var/server.log
sudo /var/apps/edge-bookmarks/cmd/main status; echo $?     # 0=运行中，3=未运行
ls -l /var/apps/python312/target/bin/python3 /usr/bin/python3 2>&1
sudo ss -ltnp | grep 8765
ls -l /var/apps/edge-bookmarks/target/app.sock              # 网关 Socket
sudo /var/apps/edge-bookmarks/cmd/main start; echo $?       # 手动启动一次
```

| `STARTUP_STATUS.txt` 内容 | 含义 | 处理 |
| --- | --- | --- |
| 文件不存在 | `main start` 从未被调用 | 应用中心点「启动」，或执行上面的手动启动 |
| `失败：未找到 Python 3` | 缺运行时 | 安装 `python312` 后再启动 |
| `失败：启动超时` | 进程崩了或端口冲突 | 看 `server.log`、`ss -ltnp \| grep 8765` |
| `成功：TCP 直连就绪` + `统一网关 Socket 已建立` | 服务没问题 | 转到第二节查入口 |
| `成功：TCP 直连就绪` + `未检测到网关 Socket` | Python 无 `AF_UNIX` 或 Socket 绑定失败 | 看 `server.log`；桌面可临时用 `http://<NAS-IP>:8765` 打开 |

## 二、服务正常但网关入口打不开

### 2.1 网关 Socket 未建立或权限不对

统一网关的链路是：`飞牛校验登录态 → 转发到 ${TRIM_APPDEST}/app.sock`。Socket 不存在、权限不允许网关进程访问，都会表现为打不开或 502。

```bash
sudo ls -l /var/apps/edge-bookmarks/target/app.sock
sudo tail -n 80 /var/apps/edge-bookmarks/var/server.log | grep -i socket
```

应用以专用用户 `edgebm` 运行，Socket 权限为 `0660`。若飞牛网关进程不在同组，需调整权限或用户组。重启应用时 `cmd/main` 会先 `rm -f` 陈旧 Socket 再重新绑定。

### 2.2 `gatewayPrefix` 与后端前缀不一致（404 / 白屏）

四处必须完全一致：

| 位置 | 值 |
| --- | --- |
| `app/ui/config` → `gatewayPrefix` | `/app/edge-bookmarks` |
| `app/ui/config` → `gatewaySocket` | `app.sock` |
| `cmd/main` → `EB_GATEWAY_PREFIX` | `/app/edge-bookmarks` |
| `cmd/main` → `EB_GATEWAY_SOCKET` | `${TRIM_APPDEST}/app.sock` |

```bash
sudo cat /var/apps/edge-bookmarks/target/ui/config
sudo grep -n GATEWAY /var/apps/edge-bookmarks/cmd/main
```

服务端会剥离前缀并给 HTML 注入 `<base href="/app/edge-bookmarks/">`；前缀对不上就会 404 或资源加载失败。

### 2.3 入口缓存

覆盖安装后「图标行为没变化」的实证解法——重启应用中心让它重读 `ui/config`：

```bash
sudo systemctl restart trim_app_center.service
```

然后 **Ctrl+F5 强制刷新**飞牛桌面，再点图标。

### 2.4 确认桌面图标与入口

v1.1.0 起只注册**一个** `type=url` 入口「Fn收藏夹同步」，点开在新页面打开管理界面，内外网复用飞牛域名。旧版的「新窗口」「局域网直连」图标已移除——找不到它们不是故障。

| 情形 | 判断 |
| --- | --- |
| 图标能开、页面空白 | 缓存或资源加载问题，按第三节看 Console |
| 图标点了没反应 | 服务没起来，回到第一节 |
| 根本没有这个图标 | 安装未完成或系统不识别网关入口，按 2.5 直接用 `http://<NAS-IP>:8765` 核对 |

### 2.5 旧版本 fnOS 不支持统一网关

`gatewayPrefix` / `gatewaySocket` 是较新的入口规范。若系统不识别，桌面图标可能不出现或点了没反应。此时直接在浏览器打开 `http://<NAS-IP>:8765` 访问，功能完全一致，只是 HTTPS/外网下需自行反代。

## 三、页面能打开但空白 / 一直转圈

浏览器按 F12 看 Console / Network：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `app.js` / `style.css` 404 | 前缀没对齐，`<base>` 指向错误路径 | 核对 2.2 的四处配置 |
| `/api/v1/...` 404 | 网关未把 `/app/edge-bookmarks/...` 完整转发 | 检查 `gatewayPrefix`；服务端已支持带前缀路由 |
| 页面正常但提示会话失效 | 令牌被重置或密码改过 | 重新用应用账号密码登录；插件侧更新密码 |

> 服务端同时接受 `/api/v1/...`（直连）与 `/app/edge-bookmarks/api/v1/...`（网关），并给 HTML 注入对应的 `<base>`。两条通道共用同一个数据库。

## 四、别把「插件连不上」当成桌面问题

管理界面能开、插件报「以下地址均探测失败」是**另一条链路**：插件需要 TCP 8765 直连、飞牛统一网关（浏览器已登录 NAS）或自己配置的反代路径。错误信息会逐条列出实际请求的 URL 与原因。

按顺序测：

```bash
# 1) 在 NAS 本机
curl http://127.0.0.1:8765/api/v1/health
# 2) 在电脑上（换成你的 NAS 地址）
curl http://<NAS-IP>:8765/api/v1/health
```

| 结果 | 结论 |
| --- | --- |
| 本机通、电脑不通 | **防火墙未放行 8765**。确认装的是含 `port-config` + `EdgeBookmarks.sc` 的包；若 NAS 手动开了防火墙，补一条 8765/tcp 入站规则 |
| 本机也不通 | 服务没起来 → 回到本文第一节查 `python312` 与 `STARTUP_STATUS.txt` |
| 两者都通，但插件仍失败 | 地址填错了：填了飞牛登录地址或 `/app/...`（被网关登录校验拦住）；改用管理端复制的配置，或按 [反向代理与统一登录地址](反向代理与统一登录地址.md) 配反代路径 |

其他要点：

- 离开内网需确保 8765 已映射，或走浏览器已登录飞牛的统一网关，或用反代路径；
- 插件设置页保留路径前缀，反代地址形如 `https://域名:端口/eb-api` 可直接填写。

详见 [统一网关与内外网](统一网关与内外网.md) 与 [反向代理与统一登录地址](反向代理与统一登录地址.md)。
