# 安装提示「无法创建应用程序目录」排查指南

> **v1.4.0 更新**：界面现代化 + 代码精简 + 开源发布，开发者统一为 oldkevin。包结构、钩子脚本与端口声明均未改动，本文全部排查方法继续适用。主包文件名为 `fn-bookmark-sync_1.4.0_all.fpk`（另有 `_x86` / `_arm` / `_all_noport` 三个变体）。
>
> **v1.3.x 已有**：服务端启动流程与数据迁移逻辑不变，仍**不生成 `token.txt`**；账号密码存 `$TRIM_PKGVAR/bookmarks.db`。
>
> 若从旧版升级后装不上，先确认下载的是 **1.4.0** 的包：旧版包名不同，混装会出现「已存在同名应用」。

> 适用：飞牛应用中心手动安装 `.fpk` 时，在创建应用目录阶段失败，应用列表里看不到应用。
>
> **已经装上了、只是点桌面图标没反应？** 那是另一条链路，请直接看 [点开无反应排查](点开无反应排查.md)。
>
> **v1.0.5 起桌面入口改用飞牛统一网关**，安装期钩子仍为零副作用；网关链路说明见 [统一网关与内外网](统一网关与内外网.md)。

## 一、先看懂这个笼统报错

fnOS 应用中心把**安装期任何非 0 退出**都包装成「无法创建应用程序目录」，真实原因不会显示。本应用的安装期钩子（`install_init` / `install_callback`）刻意设计为纯 `exit 0`：不检查环境、不建目录、不写文件。因此出现该报错时，优先怀疑下面几类原因：

| 类别 | 典型原因 |
| --- | --- |
| 包不对 | 下载了旧版本、单架构包与系统不匹配、包名与已装应用冲突 |
| manifest 字段 | `appname` / `version` / `platform` / `maintainer` 等字段格式不被当前 fnOS 接受 |
| 资源声明 | `config/resource` 的 `port-config` 指向的 `.sc` 文件缺失或格式不对 |
| 系统侧 | 卷不存在 / 未挂载、存储空间不足、`@appdata` / `@appconf` 权限异常、AppCenter 解包权限回归 |
| 残留 | 上次失败留下的同名目录 / Socket 未清理 |

## 二、快速自检清单（按顺序做）

1. **运行时**：应用中心搜索并安装官方 **`python312`**。fnOS 默认不带 Python 3，没有它服务装上也起不来（虽然装得上，但启动会失败）。
2. **包版本与架构**：确认上传的是 `fn-bookmark-sync_1.4.0_all.fpk`；若系统不识别 `platform=all`，换 `fn-bookmark-sync_1.4.0_x86.fpk` 或 `fn-bookmark-sync_1.4.0_arm.fpk`。
3. **端口声明**：若主包因端口声明安装失败，改用 `fn-bookmark-sync_1.4.0_all_noport.fpk` 对照包（`resource={}`、不含 `.sc`）。对照包能装而主包不能，说明问题在端口资源声明。
4. **只解析不安装**：用 `dry-run` 看安装器能否解析包：

```bash
sudo trim-cli app install-fpk --volume-id 1 --dry-run --yes \
    /vol1/路径/fn-bookmark-sync_1.4.0_all.fpk
```

5. **选对存储空间**：手动安装时明确选择健康、已挂载的卷，不要依赖默认值。

## 三、核对 manifest 字段

`fpk/manifest` 关键字段及约束：

| 字段 | 本应用取值 | 说明 |
| --- | --- | --- |
| `appname` | `edge-bookmarks` | 小写字母 + 数字 + 连字符，官方允许；**内部标识不可改** |
| `version` | `1.4.0` | 与产物文件名一致 |
| `display_name` | `Fn收藏夹同步` | 显示名，中文允许 |
| `platform` | `all` | 不识别时换 `x86` / `arm` 单架构包 |
| `maintainer` / `distributor` | `oldkevin` | 含空格的维护者名官方示例也允许 |
| `service_port` | `8765` | 必须与 `EdgeBookmarks.sc` 的 `src.ports` / `dst.ports` 一致 |
| `checkport` | `false` | 安装期不检查端口，避免非确定性失败 |
| `desktop_uidir` | `ui` | 桌面入口资源目录 |
| `desktop_applaunchname` | `edge-bookmarks.main` | 默认入口，必须以 appname 为前缀 |

> 若你自行改过 manifest，请先与官方示例逐字段比对；`checksum` 由打包器注入，不要手工填写。

## 四、检查资源目录与端口声明

主包必须包含以下结构：

```
manifest
app.tgz
cmd/                  安装/启动/停止钩子
config/               privilege、resource 等
ui/                   桌面入口配置
wizard/
ICON.PNG
ICON_256.PNG
EdgeBookmarks.sc      端口放行声明（与 service_port 对应）
```

`config/resource` 内容为：

```json
{"port-config": {"protocol-file": "EdgeBookmarks.sc"}}
```

`EdgeBookmarks.sc` 中应有：

```
port_forward="yes"
src.ports="8765/tcp"
dst.ports="8765/tcp"
```

> 声明了 `service_port` 就必须配套 `port-config` 与 `.sc`，否则防火墙不开放端口，会出现「应用运行中、但局域网连不上 8765」。若 `.sc` 触发安装失败，用 `_all_noport.fpk` 对照包验证。

## 五、抓日志定位（需 SSH）

飞牛桌面 → 设置 → 终端与 SN / SSH，开启后登录执行：

```bash
# 1) 系统版本
cat /etc/trim.version 2>/dev/null || trim-cli sys version 2>/dev/null

# 2) Python 3 是否可用（关键）
ls -l /var/apps/python312/target/bin/python3 /usr/bin/python3 2>&1
python3 --version 2>&1

# 3) 目标卷（只读检查）
df -h | grep -E 'vol|Filesystem'
ls -ld /vol1 /vol1/@appcenter /vol1/@appdata /vol1/@appconf 2>&1

# 4) 失败残留（只读检查）
ls -la /var/apps/ 2>/dev/null | grep -i edge

# 5) 应用中心错误日志（最关键）
sudo tail -n 150 /var/log/trim_app_center/error.log 2>/dev/null
sudo tail -n 100 /var/log/trim_app_center/info.log 2>/dev/null

# 6) 本应用自己的启动日志（若已装上）
sudo tail -n 100 /var/apps/edge-bookmarks/var/server.log 2>/dev/null
```

### 按关键字对照

| 日志 / 提示 | 原因 | 处理 |
| --- | --- | --- |
| `install_init`、`10237`、`EACCES`、`permission denied` | 安装钩子执行失败 | 确认用的是 v1.4.0（钩子已是 `exit 0`） |
| `python`、`No such file or directory`、`未找到 Python 3` | 未安装 `python312` 运行时 | 应用中心安装官方 `python312`，再点「启动」 |
| `创建应用data-share目录失败`、`@appshare` | fnOS 创建共享目录失败 | 本应用已移除 data-share；若仍出现是系统侧权限异常 |
| `20001`、存储空间不可用 | 卷不存在 / 未挂载 / 不健康 | 换一个健康存储空间，手动安装时明确选择 |
| `arch`、`platform`、`架构不支持` | 不识别 `platform=all` | 换 `fn-bookmark-sync_1.4.0_x86.fpk` / `..._arm.fpk` |
| `port`、`8765` 被占用 | 端口冲突 | 见 [部署指南](部署指南.md)「修改端口」 |
| `already exists`、`同名应用` | 旧版本残留 | 先在应用中心卸载旧应用，或清理残留目录（见第七节） |

> fnOS 部分版本存在 AppCenter 解包目录权限回归（目录被设成 `0644`），会让第三方 FPK 的安装钩子 `permission denied`。若命中，需在系统侧修正权限或升级 fnOS。

## 六、Python 3 缺失时的表现（重要）

v1.4.0 允许在**没装 python312** 的情况下先把应用装上，但服务无法启动：

- 应用中心显示「未运行」，点启动会提示「未找到 Python 3：请先…安装官方 python312 运行时」；
- 桌面图标打开是空白 / 连接失败；
- Web 界面进不去（账号库尚未初始化）。

处理顺序：应用中心安装 `python312` → 回到本应用点「启动」→ 状态变「运行中」→ 再打开桌面图标并用应用账号密码登录。安装 `python312` **不需要重装本应用**。

## 七、残留清理（可选，执行前请确认路径）

只有确认是本次失败留下的、且里面没有书签数据时才清理。下面只列不删：

```bash
ls -ld /var/apps/edge-bookmarks \
       /vol1/@appcenter/edge-bookmarks /vol1/@appdata/edge-bookmarks \
       /vol1/@appconf/edge-bookmarks 2>&1
```

确认无误后再对**具体单个路径**执行 `sudo rm -rf <路径>`。不要对 `/vol1`、`/var/apps` 这类父目录做递归删除。

## 八、如果还是不行

把下面信息发回来，可直接定位而不用再猜：

1. 上传的是哪个包（`all` / `x86` / `arm` / `all_noport`），以及安装时的完整提示；
2. `sudo tail -n 150 /var/log/trim_app_center/error.log` 输出；
3. `cat /etc/trim.version`、`python3 --version`、`df -h | grep vol` 输出。

如需自行重新打包（在有官方 `fnpack` 的环境下）：

```bash
python tools/build_fpk.py     # 生成 dist/fn-bookmark-sync_1.4.0_*.fpk 与插件 zip
```
